## Ground every convention, in this order

| | |
| :--- | :--- |
| 1. a skill, if one owns this | it already encodes the conventions, correctly |
| 2. Context7, for the real docs | current, and not recalled from memory |
| 3. stop and say so | never invent the third option |

An invented convention for something half-remembered produces work that
looks right, is not, and is internally consistent enough that nothing
downstream catches it. Reading the actual documentation is cheaper than
the review that finds it later.

## Where truth lives

Nothing here is kept current by hand. Do not introduce anything that
would need to be.

| | |
| :--- | :--- |
| code structure, callers, impact, tests | the Code Review Graph — self-maintaining |
| work, status, dependencies | GitHub issues and PRs |
| capability verdicts + reasoning | `.project/inventory.json` — 11 judged, tracked in git |
| profile, surfaces, environments | `.project/project.yaml` |

`.project/` is **tracked deliberately**. A judgment nobody can see in a
diff is one nobody notices going wrong.

## Environments

- **development**, no runtimes described
- **production**, no runtimes described

Default branch is `feat/crew-protocol`. An environment is healthy only
when the *integrated* system works — a green frontend against a stale
backend is not healthy, it just looks deployed.

## Working here

```bash
devctl health                     # what state is this repo in
devctl change preflight "<ask>"   # has this been asked for already
devctl packet <issue>             # the brief for one issue
devctl test changed               # the tests covering what moved
```

**Never create a GitHub issue without `devctl github resolve-work`.**
Building a second implementation of something that exists is the most
expensive failure available here, and it is always preventable.
